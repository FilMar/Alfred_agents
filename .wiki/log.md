## [2026-07-21] ingest | Third Identity (ti) and Third Log (tl): founded via Archimede (reconstructed entry)
**This entry reconstructs one accidentally destroyed**: a background agent wiped `.wiki/log.md` with a broken `sed`/`mv` while trying to append to it; the file was restored from git HEAD, which did not yet contain the original entry. This reconstruction is based on [ti_module](ti_module) and [tl_module](tl_module), not on the lost original text.

`ti` (Third Identity): a thin CLI over a dedicated Qdrant collection (`pi_identity`) storing context→action rules (`if`/`do`/`tags`) — distinct from `tb`'s semantic memory, which answers "what do I know about X" rather than "what should happen given context X". A `do` entry can be a behavior, a dispatch to a skill/`th` member, or a `tb` lookup hint (a search term, never a frozen note id). Deliberately a dumb client: no auto-merge, no similarity judgment, no internal LLM call — the merge/dedup decision stays with the caller, same discipline as `tb search` → `tb add`. Reuses `tools/tb/src/infra.ts` without modification.

`tl` (Third Log): a unified, structured event log extracted out of `th`'s local SQLite tracking, shared by `th`, `tb`, `ti`, and future producers. Not a CLI — a REST API (`Bun.serve`, hosted on the Rasp) called via `curl`/HTTP, SQLite-backed (`TL_DB`), a single `events` table with a fixed envelope (`id`/`timestamp`/`source`/`actor`/`context`/`outcome`/`tags`) plus a free-form `metadata` payload — deliberately one table, not one per source, since the point is that one query spans every source. Fire-and-forget client behavior: short timeout, zero retry, failures degrade to "no log entry" and never block the caller.

Both founded via Archimede in the same design conversation; both concretize gaps identified in [procedural_memory_gaps](procedural_memory_gaps).

## [2026-07-15] reconcile | Wake-window scheduling e audit graduale per il Raspberry Orchestrator

Semplificato il Boot-Callback Pattern: niente più attesa indefinita (`AWAITING_BOOT`).
