## Decision

Dijkstra has one sheet per language (rust, python, typescript, bash): a catalog of tools that make code shorter. Examples are `macro_rules!`, `derive`, generics, tables, decorators, `replace` as a builder and parametrized tests. Each tool says what it replaces, when it pays and which owner rule limits it. A language with no sheet goes through seven questions first. The sheet is per language, and the rules come from the owner: a Python file from ritchie and one from pike read the same sheet.

Shared limits, written once: a macro, a decorator or generated code never holds an assert. No abstraction serves only one user. Control flow stays visible. There is no inheritance and no recursion.

## Why

The first draft treated "a shorter way" as standard library idioms. The user pointed out that the real gains come from structural tools such as a builder in Python or a macro in Rust, and these differ per language. They also clash with ritchie's rules in a different way in each language, so each one needs its own terms.

`contract_report.py` reads the text, so it cannot see an assert generated by a macro, and neither can a reader. In the Rust test this kept two `scale_*` functions apart: merging them would have meant a macro holding the assert.
